[Mini Blockfrost](./minibf) is checked against Blockfrost's own integration suite, [blockfrost/blockfrost-tests](https://github.com/blockfrost/blockfrost-tests). The suite sends the requests it recorded against hosted Blockfrost to the server under test and compares each response with the recorded one. This page states the result at the beta.1 candidate on each network.

Dolos does not pass the whole suite on any network. The tables state what it passes and fails, which failures come from Dolos, and which come from the suite's recorded responses or from Dolos's design.

## What the failures are

Not every failure is a Dolos defect. Each one falls in one of these classes:

| Class                                                             | Mainnet | Preprod | Preview |
| ----------------------------------------------------------------- | ------: | ------: | ------: |
| Dolos defect: the response is wrong or incomplete                 |       3 |       1 |       5 |
| Deep page refused by the scan limit                               |      79 |      20 |       3 |
| Recorded response no ledger-correct server can return             |       2 |       2 |       1 |
| Pool off-chain document changed or gone since it was registered   |       3 |       0 |       0 |
| **Total**                                                         |  **87** |  **23** |   **9** |

- **Scan limit.** Dolos refuses a page whose position needs a scan past `max_scan_items` instead of walking the history to reach it ([dolos#1270](https://github.com/txpipe/dolos/issues/1270), HTTP 400 when `page * count` is more than `max_scan_items`). The suite asks for some pages deep in long listings, and these tests fail by that design. They are pages of `/addresses/{address}/transactions` and `/txs`, `/assets/{asset}/transactions` and `/txs`, and `/epochs/{number}/stakes`. [Operational limits](#operational-limits) gives the depth.
- **Recorded responses no ledger-correct server can return.** Two cases:
  - `/`: the recorded response's `url` is Blockfrost's own, `https://blockfrost.io/`, and the suite compares it exactly, so no other `public_url` makes the test pass. Dolos reports `url` only when `public_url` is set.
  - Vote redeemers, on `/scripts/{script_hash}/redeemers`. Dolos lists the script's vote-purpose redeemers. Hosted Blockfrost leaves `script_hash` empty on vote-purpose redeemers, so its script listings, and the responses the suite recorded from them, omit the script's votes. Dolos's answer is the ledger's ([dolos#1426](https://github.com/txpipe/dolos/issues/1426), Dolos includes valid vote redeemers that Blockfrost leaves out).
- **Pool off-chain metadata is fetched live.** Dolos fetches a pool's metadata document when asked for it and checks it against the hash the pool registered. A document changed after registration yields `HASH_MISMATCH`, and one that is gone yields an error or nulls. Blockfrost serves the copy it stored when the hash last matched. This is a difference of design, not a defect. It affects `/pools/{pool_id}/metadata`, `/txs/{hash}/pool_updates` and every route that serves pool off-chain metadata.

## Operational limits

- **Page depth.** On 21 routes a page is refused with `400 pagination scan limit exceeded` when `page × count` is more than `max_scan_items` (3000 by default), before anything is read. The deepest page is then 30 at `count=100`, 600 at `count=5` and 3000 at `count=1`. The routes are `/accounts/{stake_address}/delegations`, `/mirs`, `/registrations`, `/transactions` and `/withdrawals`; `/addresses/{address}/transactions` and `/txs`; `/assets/{asset}/transactions` and `/txs`; `/epochs/{number}/stakes`; `/governance/committee/votes` and `/governance/committee/{cc_id}/votes`; `/governance/dreps`, `/governance/dreps/{drep_id}/updates` and `/votes`; both proposal `/votes` routes; `/metadata/txs/labels/{label}` and its `/cbor`; `/pools/{pool_id}/votes`; and `/scripts/{script_hash}/redeemers`.
- **Blocks read per request.** On `/scripts/{script_hash}/redeemers` and the six vote listings, `max_scan_items` also caps the blocks one request reads. A page whose matches lie past that many of the key's blocks answers the same 400, whatever its page and count.
- **503.** A heavy-scan request waits at most `heavy_scan_queue_seconds` (5 s) for one of `max_concurrent_heavy_scans` (32) slots, then gets `503 Service Unavailable` with `Retry-After: 1` (see [Heavy scans](./minibf#heavy-scans)).
- **504.** Every request still running after `request_timeout_seconds` (120 s) gets `504 Gateway Timeout`. Inside the page limit, a deep page of a heavy key comes close to it: on mainnet, page 30 at `count=100` of `/addresses/{address}/transactions` for one heavy script address took 93.3 s on its own, so on a busier node it can be a 504.
- **Response times under production traffic.** On the mainnet instance serving production traffic, with an 8 GiB memory limit over network block storage, heavy reads took 3 to 5 times as long as on a local node with an SSD. `/pools/{pool_id}` took about 8 s, since it sums live stake over every account on each request; `/pools/extended` pages took 8.6 to 9.8 s; the heaviest address bodies took 10.5 to 33 s; and `/network` took about 7 s whenever its 30-second cache had lapsed. At that ratio the deepest admitted page of a heavy key would very likely pass the 120-second deadline there and answer 504.

## Running the suite yourself

1. Run Dolos with Mini Blockfrost enabled, synced to the tip of the network you test. Set `token_registry_url` in `[serve.minibf]`: `https://tokens.cardano.org` on mainnet, `https://metadata.world.dev.cardano.org` on the testnets. Without it the asset off-chain metadata tests fail.
2. Clone the suite and check out the commit you want to test against, then install its dependencies with pnpm (Node 20 or later, with corepack enabled, which provides the pnpm version the suite's `package.json` pins):

   ```shell
   git clone https://github.com/blockfrost/blockfrost-tests.git
   cd blockfrost-tests
   git checkout da08369070a97366f36ad24d4f446ae73a2c2fd3
   pnpm install --frozen-lockfile
   ```

3. Write `endpoints-allowlist.json` at the suite's root: a JSON array of the endpoint paths to run. The suite skips every test of an endpoint not in it. Take the paths from the [Coverage](./minibf#coverage) table and use Blockfrost's parameter names, or the suite refuses the file and runs nothing: `{subject}` is `{asset}`, `{epoch}` is `{number}`, a pool's `{id}` is `{pool_id}`, and `{tx_hash}` under `/txs/` is `{hash}`. These runs left out `/tx/submit`, which needs a funded wallet, and `/scripts/{script_hash}/utxos`. The suite does test the last one, so you can include it. They used no `endpoints-ignorelist.json`, the suite's list of tests to skip by ID.
4. Export the settings and run the network's tests:

   ```shell
   export SERVER_URL=http://localhost:3000
   export NETWORK=mainnet
   export PROJECT_ID=unused
   pnpm test:mainnet
   ```

   `SERVER_URL` is the instance's base URL: its `listen_address`, plus its `route_prefix` when one is set (for example `http://localhost:3000/api/v0`). `PROJECT_ID` only has to be set: the suite sends every request to `SERVER_URL` and compares the response with the one it recorded. These runs left `BLOCKCHAIN_STATE_SETUP` unset. The checks that need the current tip, such as slot and confirmation counts, are not skipped then: they only require a non-negative number, without the bound the tip gives. Set it to check them against the tip of the server under test. Use `test:preprod` or `test:preview` for the testnets, with `NETWORK` to match.

Each test has 15 seconds by default, some up to a minute, and the tests run concurrently, so run one network at a time on an otherwise idle machine, and repeat a run once the node's caches are warm before reading its timeouts. After the run, check that every endpoint in the allowlist ran at least one test.
