[Mini Blockfrost](./minibf) is checked against Blockfrost's own integration suite, [blockfrost/blockfrost-tests](https://github.com/blockfrost/blockfrost-tests). The suite sends the requests it recorded against hosted Blockfrost to the server under test and compares each response with the recorded one. This page summarises the latest run on each network.

Dolos does not pass the whole suite on any network yet. The tables state what it passes and fails, and the failures that come from Dolos are listed below as known gaps.

## What the failures are

Not every failure is a Dolos defect. Each one falls in one of these classes:

| Class                                                          | Mainnet | Preprod | Preview |
| -------------------------------------------------------------- | ------: | ------: | ------: |
| Dolos gap: the response is wrong or incomplete                 |      34 |       2 |       7 |
| Timeout: no answer within the suite's 15 seconds               |       7 |       0 |       0 |
| Deep page refused by the scan limit                            |      79 |      20 |       3 |
| Recorded response predates a change on chain or at its source  |       3 |       1 |       0 |
| Off-chain document on IPFS not fetched in time                 |       2 |       0 |       0 |
| Dolos lists a redeemer the recorded response leaves out        |       1 |       1 |       0 |
| **Total**                                                      | **126** |  **24** |  **10** |

- **Scan limit.** Dolos refuses a page whose position needs a scan past `max_scan_items` (see [Configuration](./minibf#configuration)) instead of walking the history to reach it ([dolos#1270](https://github.com/txpipe/dolos/issues/1270), HTTP 400 when `page * count` is more than `max_scan_items`). The suite asks for some pages deep in long listings, and these tests fail by that design.
- **Recorded responses that moved on.** Pool metadata documents that were changed or removed at their host, and an account that delegated its vote after the response was recorded.
- **Vote redeemers.** On `/scripts/{script_hash}/redeemers`, Dolos lists the vote-purpose redeemers of a script that Blockfrost's recorded response omits ([dolos#1426](https://github.com/txpipe/dolos/issues/1426), Dolos includes valid vote redeemers that Blockfrost leaves out).

### Timeouts

On mainnet, five forms of `/epochs/{epoch}/blocks/{pool_id}` for one epoch and pool timed out, intermittently, under the suite's concurrent requests. The other two are second pages of `/assets/{subject}/txs` for an asset with a long history, where the cost of a page grows with its depth. The two IPFS failures are proposal `/metadata` reads whose anchor lives on IPFS and was not fetched within the 15 seconds.

## Running the suite yourself

1. Run Dolos with Mini Blockfrost enabled, synced to the tip of the network you test. Set `token_registry_url` in `[serve.minibf]`: `https://tokens.cardano.org` on mainnet, `https://metadata.world.dev.cardano.org` on the testnets. Without it the asset off-chain metadata tests fail.
2. Clone the suite and check out the commit you want to test against, then install its dependencies (Node 20 or later, with corepack enabled):

   ```shell
   git clone https://github.com/blockfrost/blockfrost-tests.git
   cd blockfrost-tests
   git checkout f5bfe322c47131e2378ef85cf50c277dd1cce8b9
   yarn install
   ```

3. Write `endpoints-allowlist.json` at the suite's root: a JSON array of the endpoint paths to run. The suite skips every test of an endpoint not in it. Take the paths from the [Coverage](./minibf#coverage) table and use Blockfrost's parameter names, or the suite refuses the file and runs nothing: `{subject}` is `{asset}`, `{epoch}` is `{number}`, a pool's `{id}` is `{pool_id}`, and `{tx_hash}` under `/txs/` is `{hash}`. These runs left out three endpoints: `/tx/submit`, which needs a funded wallet, `/metrics`, which the suite has no tests for (Dolos's own `/metrics` serves Prometheus metrics, not Blockfrost's usage metrics), and `/scripts/{script_hash}/utxos`. The suite does test the last one, so you can include it.
4. Export the settings and run the network's tests:

   ```shell
   export SERVER_URL=http://localhost:3000
   export NETWORK=mainnet
   export PROJECT_ID=unused
   yarn test:mainnet
   ```

   `PROJECT_ID` only has to be set: the suite sends every request to `SERVER_URL` and compares the response with the one it recorded. These runs left `BLOCKCHAIN_STATE_SETUP` unset, so the checks that need the current tip, such as slot and confirmation counts, passed without being made; set it to `1` to make them against the server under test. Use `test:preprod` or `test:preview` for the testnets, with `NETWORK` to match.

Each test has 15 seconds by default, some up to a minute, and the tests run concurrently, so run one network at a time on an otherwise idle machine, and repeat a run once the node's caches are warm before reading its timeouts. After the run, check that every endpoint in the allowlist ran at least one test.
