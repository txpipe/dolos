A Cardano node keeps the settled part of the chain in its _ImmutableDB_. If you run a `cardano-node`, or hold a database a Mithril download left, Dolos can replay it directly: no download, and no network until the replay is done.

`bootstrap immutabledb` runs the same replay as [`bootstrap mithril`](./mithril) does after its download. What differs is the trust: nothing certifies a local database, so the one check is that it belongs to the configured network. The network magic the node records beside `immutable/`, in `protocolMagicId`, must be the configuration's; a database of another network is refused before anything is written.

## Execution

Point the command at the node's database directory, the one holding `immutable/` and `protocolMagicId`:

```sh
dolos bootstrap immutabledb --source /var/lib/cardano/db
```

The database is only read, never written. The replay imports every block into the archive and rebuilds the ledger state from them, which takes from minutes to hours depending on the network.

In addition to the [bootstrap flags](../bootstrap), the command takes:

| arg | description | default |
| --- | ----------- | ------- |
| `--source <PATH>` | the node database directory; required | |
| `--continue` | resume an interrupted replay from its committed position | `false` |
| `--stop-epoch <N>` | stop once the ledger reaches epoch `N` | none |
| `--chunk-size <N>` | blocks per batch; more is faster but uses more memory | `500` |

<Aside type="note">
An interrupted replay keeps what it committed. Run the command again with `--continue` to resume from there.
</Aside>

## After the replay

The ImmutableDB stops short of the tip: the node's most recent blocks are still volatile. Follow the chain from the configured upstream to reach it, which can be the same local node:

```toml
[upstream]
peer_address = "localhost:30000"
```

```sh
dolos daemon
```

See [operation modes](../operations/modes) for `daemon`, `serve` and `sync catchup`.
